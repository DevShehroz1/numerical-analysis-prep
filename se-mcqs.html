Topic 1 — Introduction to Software Engineering

Q1. What is software?

  • a) Only the hardware components of a computer
  • b) Programs, data, and instructions that enable computers to perform tasks
  • c) Operating system only
  • d) Physical storage devices
Answer: b) Software is programs, data, and instructions that enable computers to perform tasks. (Webster's Dictionary, 1981)

Q2. Which of the following is NOT a software function?

  • a) Data processing and manipulation
  • b) User interface interactions
  • c) Manufacturing physical products
  • d) Security and access control
Answer: c) Software does not manufacture physical products. It handles data, calculations, I/O, files, networking, security, errors, scheduling, databases, and graphics.

Q3. Which is the correct order of software application levels (highest to lowest)?

  • a) Hardware Logic → System Software → Application Software → End-user Software
  • b) End-user Software → Application Software → System Software → Hardware Logic
  • c) System Software → Hardware Logic → Application Software → End-user Software
  • d) Application Software → System Software → End-user Software → Hardware Logic
Answer: b) From highest (user-facing) to lowest (hardware): End-user → Application → System → Hardware Logic.

Q4. Generic software products are:

  • a) Built for one specific customer only
  • b) Stand-alone systems marketed and sold to any customer
  • c) Embedded systems
  • d) Air traffic control systems
Answer: b) Generic products are stand-alone systems sold to any customer (e.g., MS Office, CAD software). Customized products are built for a specific customer.

Q5. Who gave the famous definition: "The establishment and use of sound engineering principles to obtain economically software that is reliable and works on real machines"?

  • a) Pressman (1992)
  • b) Bauer (1972)
  • c) Wang and King (2000)
  • d) Sommerville (2011)
Answer: b) Bauer (1972) gave this classic definition of Software Engineering.

Q6. According to Pressman, Software Engineering consists of three key elements. Which is NOT one of them?

  • a) Methods
  • b) Tools
  • c) Procedures
  • d) Hardware
Answer: d) Pressman (1992): SE = Methods + Tools + Procedures. Hardware is not part of this definition.

Q7. Which of the following is NOT a software characteristic (according to Brooks)?

  • a) Complexity
  • b) Conformity
  • c) Manufacturability
  • d) Invisibility
Answer: c) The 4 software characteristics are: Complexity, Conformity, Changeability, Invisibility. Software is NOT manufactured — it is developed.

Q8. Software is considered "invisible" because:

  • a) It cannot be seen on a screen
  • b) It is a virtual object, not physical
  • c) It is written in binary
  • d) It is always encrypted
Answer: b) Software is a virtual/logical object. You can't touch or see it physically like hardware.

Q9. The Software Crisis of the 1960s-1980s was mainly caused by:

  • a) Lack of computers
  • b) Growing complexity of software, lack of structured methods, high cost and frequent failures
  • c) Too many programmers
  • d) Too much testing
Answer: b) The software crisis was due to complexity growth, lack of proper engineering methods, and high cost/failure rates. It led to the creation of Software Engineering as a discipline.

Q10. Which software process activity is concerned with "defining what the software should do"?

  • a) Software development
  • b) Software specification
  • c) Software validation
  • d) Software evolution
Answer: b) Software specification is where customers and engineers define what is to be produced and its constraints.

Topic 2 — Models Overview

Q11. The Big Bang model of software development is characterized by:

  • a) Detailed planning and testing
  • b) Little or no planning, little or no formal testing
  • c) Multiple iterative sprints
  • d) Customer involvement at every step
Answer: b) Big Bang combines people, money, and resources without planning. The result could be great software, terrible software, or nothing at all.

Q12. In the Build & Fix model:

  • a) Bugs are fixed before release
  • b) No testing is done; problems are fixed through usage
  • c) Every module is formally verified
  • d) Only experts can use it
Answer: b) Build & Fix has no testing. Bugs are found through customer usage and fixed by the vendor. The process itself is not improved.

Q13. Which of the following is NOT a cause of software failure?

  • a) Lack of user participation
  • b) Changing requirements
  • c) Well-defined system requirements
  • d) Poor project management
Answer: c) Well-defined requirements HELP success. BADLY defined requirements cause failure.

Q14. SDLC stands for:

  • a) System Development Language Code
  • b) Software Development Life Cycle
  • c) Structured Data Logic Chain
  • d) System Design Level Control
Answer: b) Software Development Life Cycle.

Q15. The correct order of SDLC phases is:

  • a) Design → Analysis → Development → Testing → Deployment → Maintenance
  • b) Analysis → Design → Development → Testing → Deployment → Maintenance
  • c) Testing → Design → Development → Analysis → Deployment → Maintenance
  • d) Development → Testing → Analysis → Design → Deployment → Maintenance
Answer: b) Analysis & Planning → Design → Development → Testing → Deployment → Maintenance.

Q16. Plan-driven processes are characterized by:

  • a) Incremental planning based on feedback
  • b) All process activities planned in advance, progress measured against plan
  • c) No planning at all
  • d) Customer does all the planning
Answer: b) Plan-driven processes plan everything in advance. Agile plans incrementally.

Q17. Which is NOT one of the four main software process activities?

  • a) Software specification
  • b) Software development
  • c) Software validation
  • d) Software marketing
Answer: d) The 4 activities are: Specification, Development, Validation, Evolution. Marketing is not one of them.

Q18. General issues that affect most software include:

  • a) Heterogeneity, Business change, Security and trust
  • b) Graphics only
  • c) Just hardware speed
  • d) Programming language version
Answer: a) Three general issues: Heterogeneity (different devices/networks), Business/social change, Security and trust.

Topic 3 — Waterfall Model

Q19. How many phases does the Waterfall model have?

  • a) 3
  • b) 4
  • c) 5
  • d) 6
Answer: c) 5 phases: Requirements Analysis, System Design, Implementation & Unit Testing, Integration & System Testing, Operation & Maintenance.

Q20. In the Waterfall model, the next phase starts:

  • a) Anytime, in parallel with previous phases
  • b) Only after the previous phase has finished and been signed off
  • c) Before the previous phase begins
  • d) Only if the customer requests it
Answer: b) Waterfall is sequential. Each phase must be completed and approved before the next begins.

Q21. The longest phase in the Waterfall model is usually:

  • a) Requirements
  • b) Design
  • c) Implementation
  • d) Operation and Maintenance
Answer: d) Operation and Maintenance is normally the longest phase — fixing errors, enhancing features, adapting to new requirements over years.

Q22. Waterfall model is best suited for:

  • a) Projects with constantly changing requirements
  • b) Small experimental apps
  • c) Large systems engineering projects with well-understood, stable requirements
  • d) Unknown technologies
Answer: c) Waterfall works when requirements are stable and well-understood, especially for large coordinated projects across multiple sites.

Q23. Which is a DISADVANTAGE of Waterfall?

  • a) Good process visibility
  • b) Inflexible, hard to respond to changing requirements
  • c) Quality control
  • d) Cost control
Answer: b) Waterfall's rigid sequential nature makes it hard to accommodate changes. The others are advantages.

Q24. In Waterfall, unit testing happens during which phase?

  • a) Requirements analysis
  • b) System and software design
  • c) Implementation and Unit Testing
  • d) Operation and maintenance
Answer: c) Unit testing happens alongside implementation — each unit is tested as it is coded.

Q25. Which of these is an ADVANTAGE of Waterfall?

  • a) Handles changing requirements easily
  • b) Fast delivery of partial software
  • c) Process visibility with clear documents at each phase
  • d) No need for customer involvement
Answer: c) Waterfall provides excellent process visibility, quality control, and cost control because each phase produces signed-off documents.

Q26. What does feedback in Waterfall mean?

  • a) Customers give reviews
  • b) Later phases can feed information back to earlier phases when problems are found
  • c) Testers write reports
  • d) Managers get weekly updates
Answer: b) In practice, stages overlap and feed info back. E.g., during coding, design problems may be found — requiring changes to the design phase.

Topic 4 — V-Model

Q27. V-Model is also called:

  • a) Iterative Model
  • b) Verification and Validation Model
  • c) Velocity Model
  • d) Vertical Model
Answer: b) V-Model stands for Verification and Validation Model, emphasizing testing at every stage.

Q28. V-Model is derived from which model?

  • a) Agile
  • b) Spiral
  • c) Waterfall
  • d) Scrum
Answer: c) V-Model is an extension of the Waterfall model but emphasizes verification/validation (testing) at each phase.

Q29. In V-Model, each development phase is matched with:

  • a) A customer meeting
  • b) A corresponding testing phase
  • c) A budget review
  • d) A coding task
Answer: b) Each dev phase has a matching test phase. E.g., Requirements ↔ Acceptance Testing, System Design ↔ System Testing, Unit Design ↔ Unit Testing.

Q30. In V-Model, the left side represents ___ and the right side represents ___:

  • a) Testing / Development
  • b) Development / Testing
  • c) Design / Requirements
  • d) Customer / Developer
Answer: b) Left side = Development phases (Requirements, Design, Coding). Right side = Testing phases corresponding to each dev phase.

Q31. V-Model is considered suitable for:

  • a) Small experimental projects with unclear requirements
  • b) Projects requiring disciplined approach with clear testing
  • c) Research projects only
  • d) Only hardware projects
Answer: b) V-Model is disciplined and widely used when testing/verification is critical (medical, aerospace, banking).

Topic 5 — Incremental & Iterative Models

Q32. The Incremental Model involves:

  • a) Building the entire system at once
  • b) Developing in small parts, each adding new functionality
  • c) Only testing, no development
  • d) Copying an existing system
Answer: b) The system is built in increments. Each iteration passes through requirements, design, coding, and testing, adding new functions.

Q33. Which is a BENEFIT of the Incremental model?

  • a) Process is completely invisible
  • b) Customer can get and use partial software early
  • c) No testing needed
  • d) No customer involvement
Answer: b) Customers get working software earlier than with Waterfall. Changes are cheaper to accommodate.

Q34. A PROBLEM with Incremental development is:

  • a) Customer cannot see progress
  • b) System structure tends to degrade as new increments are added
  • c) It always fails
  • d) It is too slow
Answer: b) As more increments are added without refactoring, the system architecture may become messy and harder to maintain.

Q35. Iterative model is best when:

  • a) Requirements are fully known and fixed
  • b) Requirements are not fully known, the project is complex, or innovation is required
  • c) You have unlimited time
  • d) There is no customer
Answer: b) Iterative works well when you don't know everything upfront — you develop, review, improve, repeat.

Q36. In the Search Engine example (iterative model), Iteration 1 is:

  • a) Add AI to understand intent
  • b) Basic search bar returning results by keyword matching
  • c) Add ranking
  • d) Add autocomplete
Answer: b) Iteration 1 = basic keyword search. Later iterations add ranking, autocomplete, AI — each responding to user feedback.

Q37. The Incremental model combines elements of:

  • a) Waterfall and iterative prototyping
  • b) Big Bang and Build & Fix
  • c) V-Model and Agile only
  • d) DevOps only
Answer: a) Incremental combines Waterfall's structured phases with the iterative philosophy of prototyping.

Q38. Which is TRUE about Iterative vs Incremental?

  • a) They are the same thing
  • b) Incremental = adding new features; Iterative = refining the same system through reviews
  • c) Iterative only works for games
  • d) Incremental cannot handle changes
Answer: b) Incremental adds more chunks. Iterative refines the existing product through repeated review cycles.

Q39. In Incremental model, each iteration goes through:

  • a) Only coding
  • b) Requirements, design, coding, testing phases
  • c) Only testing
  • d) Only deployment
Answer: b) Each increment is a mini waterfall cycle: requirements → design → code → test → deliver.

Topic 6 — Prototype Model

Q40. The Prototype model was developed to overcome the shortcomings of:

  • a) Agile
  • b) Scrum
  • c) Waterfall
  • d) Kanban
Answer: c) Prototype model was created to overcome Waterfall's rigidity, especially when requirements are unclear.

Q41. Which of these is NOT a phase in the Prototype model?

  • a) Communication
  • b) Quick design
  • c) Deployment, delivery, feedback
  • d) Sprint planning
Answer: d) Sprint planning is from Scrum. Prototype phases: Communication, Quick design, Modeling quick design, Construction of prototype, Deployment/delivery/feedback.

Q42. A throw-away prototype:

  • a) Is used as the final product
  • b) Is discarded after development; not a good basis for production
  • c) Is sold separately
  • d) Is stored forever
Answer: b) Throw-away prototypes are discarded after they help refine requirements. They are not documented or structured for production use.

Q43. Which is a PROBLEM with prototyping?

  • a) Prototype may not be used the same way as the final system
  • b) Customer sees early results
  • c) Improves usability
  • d) Better design quality
Answer: a) Testers may not use the prototype the way real users will. Response times differ, training is inadequate.

Q44. Prototyping is best used when:

  • a) Requirements are fully understood
  • b) Requirements are unclear and need refinement
  • c) No customer is available
  • d) Budget is unlimited
Answer: b) Prototype helps clarify requirements when customers don't know exactly what they want.

Q45. A benefit of prototyping is:

  • a) No code needed
  • b) Improved system usability and closer match to users' real needs
  • c) Prototype becomes the final product
  • d) No testing needed
Answer: b) Benefits include better usability, closer match to real needs, improved design, reduced effort.

Topic 7 — Agile & Scrum

Q46. Agile methods were created to overcome the problems of:

  • a) Heavy, documentation-focused software methods of 1980s-90s
  • b) Programming languages
  • c) Database design
  • d) Hardware costs
Answer: a) Agile was born from dissatisfaction with the heavy overhead of 1980s-90s software processes.

Q47. The Agile Manifesto values Individuals and interactions over:

  • a) Working software
  • b) Customer collaboration
  • c) Processes and tools
  • d) Responding to change
Answer: c) Agile Manifesto: "Individuals and interactions OVER processes and tools".

Q48. Which is NOT one of the 4 Agile Manifesto values?

  • a) Working software over comprehensive documentation
  • b) Customer collaboration over contract negotiation
  • c) Responding to change over following a plan
  • d) Managers over team members
Answer: d) The 4 values are: Individuals/interactions, Working software, Customer collaboration, Responding to change. Managers over team is NOT a value.

Q49. Scrum has how many phases?

  • a) 2
  • b) 3
  • c) 5
  • d) 7
Answer: b) 3 phases: Outline Planning, Sprint Cycles, Project Closure.

Q50. A Sprint in Scrum is typically:

  • a) 1 day
  • b) 2-4 weeks
  • c) 6 months
  • d) 1 year
Answer: b) Sprints are fixed-length, normally 2-4 weeks.

Q51. The Scrum Master's main role is to:

  • a) Write all the code
  • b) Facilitate the team, arrange meetings, protect from distractions, track backlog
  • c) Talk directly to customers all day
  • d) Test software
Answer: b) Scrum Master is a facilitator: arranges daily meetings, tracks backlog, records decisions, measures progress, protects team from external distractions.

Q52. The Product Backlog is:

  • a) Old discarded features
  • b) The list of work to be done on the project
  • c) Bug reports only
  • d) Customer complaints
Answer: b) Product Backlog is the prioritized list of all work/features to be done on the project.

Q53. Daily Scrum meetings are:

  • a) Long 2-hour planning sessions
  • b) Short daily meetings where team members share progress, problems, and plans
  • c) Customer feedback sessions
  • d) Budget reviews
Answer: b) Short daily stand-ups where each member discusses yesterday's progress, today's plan, and blockers.

Q54. Scaling UP agile means:

  • a) Using agile to develop large software systems that can't be built by a small team
  • b) Introducing agile across a large organization
  • c) Training more managers
  • d) Buying bigger computers
Answer: a) Scaling UP = for LARGE systems. Scaling OUT = for ORGANIZATIONAL adoption across many teams.

Q55. Which is NOT an Agile principle?

  • a) Customer involvement
  • b) Incremental delivery
  • c) Extensive documentation first
  • d) Embrace change
Answer: c) Agile values working software OVER comprehensive documentation. Principles: customer involvement, incremental delivery, people not process, embrace change, maintain simplicity.

Topic 8 — Software Requirements

Q56. A requirement is:

  • a) Only a code module
  • b) A description of system services and constraints
  • c) Just a test case
  • d) A bug report
Answer: b) Requirements describe the services the system should provide and the constraints under which it operates.

Q57. Functional requirements describe:

  • a) How fast the system must be
  • b) What services the system should provide
  • c) Hardware costs
  • d) Programming language used
Answer: b) Functional = what the system SHALL DO. Non-functional = what the system SHALL BE (fast, secure, etc.).

Q58. Non-functional requirements include:

  • a) User login function
  • b) Search feature
  • c) Response time, reliability, security, performance
  • d) Print receipt button
Answer: c) Non-functional = constraints on the system: speed, reliability, security, usability, maintainability, performance.

Q59. User requirements are written for:

  • a) Developers only
  • b) Customers, in natural language, with diagrams
  • c) Testers only
  • d) Managers only
Answer: b) User requirements are natural-language statements (+ diagrams) of services, written FOR CUSTOMERS.

Q60. System requirements are written for:

  • a) End users only
  • b) A structured document as a contract between client and contractor
  • c) Marketing team
  • d) Hardware vendors
Answer: b) System requirements are structured, detailed, written as a contract between client and contractor.

Q61. Domain requirements are derived from:

  • a) User preferences
  • b) The application domain (industry/field) of the system
  • c) Programming language rules
  • d) Budget constraints
Answer: b) Domain requirements come from the application domain (e.g., banking rules, medical protocols) and can be functional or non-functional.

Q62. Which is a functional requirement for an online shopping app?

  • a) Pages must load in less than 2 seconds
  • b) The system shall allow users to add items to a cart
  • c) 99% uptime
  • d) Works on Chrome browser
Answer: b) "Add to cart" is an action = functional. The others are non-functional (performance, reliability, portability).

Q63. Functional requirements specification should be:

  • a) Vague and open to interpretation
  • b) Complete and consistent
  • c) Written only in code
  • d) Only verbal
Answer: b) Functional requirements must be complete (all services defined) and consistent (no contradictions).

Topic 9 — Feasibility, CIA Triad, OOP

Q64. A Feasibility Study is conducted:

  • a) After the software is complete
  • b) Before committing to a project to decide: go ahead / don't go ahead / think again
  • c) Only during testing
  • d) After deployment
Answer: b) Feasibility study is done BEFORE committing. It leads to decisions and a budget request.

Q65. The CIA Triad stands for:

  • a) Central Intelligence Agency
  • b) Confidentiality, Integrity, Availability
  • c) Computing, Internet, Applications
  • d) Code, Information, Access
Answer: b) CIA Triad: Confidentiality (only authorized access), Integrity (data is correct), Availability (system accessible when needed).

Q66. In OOP, a Class is:

  • a) An instance of an object
  • b) A user-defined data type that acts as a blueprint for objects
  • c) A function
  • d) A variable
Answer: b) Class is a blueprint. Object is an instance of a class with specific data.

Q67. Methods in OOP are:

  • a) Variables that store data
  • b) Functions defined inside a class that describe behaviours of an object
  • c) Classes
  • d) Objects
Answer: b) Methods = functions inside a class that describe what an object can do.

Q68. Software reuse means:

  • a) Running the same program twice
  • b) Using existing assets (libraries, modules, components, code) to solve different problems
  • c) Copying code without permission
  • d) Re-installing software
Answer: b) Reuse = using existing libraries, components, COTS assets, design patterns to save time, cost, and improve reliability.

Quick Theory Answers

If Q1 is a theory question, here are key short answers ready to go:

Define Software Engineering

Software Engineering is a systematic, disciplined, time-and-cost-effective technique for developing software. According to Bauer (1972), it is "the establishment and use of sound engineering principles to obtain economically software that is reliable and works on real machines."

What are the 4 Software Characteristics?

  1. Complexity: Software is developed not manufactured, no two parts are alike, hard to estimate effort
  2. Conformity: Custom-built, unique to each project
  3. Changeability: Needs constant modification as requirements change
  4. Invisibility: Virtual object, not physical, cannot be touched

What are the 4 Software Process Activities?

  1. Specification: Define what the software should do
  2. Development: Design and program the software
  3. Validation: Check the software meets customer needs
  4. Evolution: Modify software to meet changing requirements

Waterfall Model Phases

  1. Requirements Analysis and Definition
  2. System and Software Design
  3. Implementation and Unit Testing
  4. Integration and System Testing
  5. Operation and Maintenance

Agile Manifesto (4 Values)

  1. Individuals and interactions over processes and tools
  2. Working software over comprehensive documentation
  3. Customer collaboration over contract negotiation
  4. Responding to change over following a plan

Scrum Phases

  1. Outline Planning: Establish objectives, design architecture
  2. Sprint Cycles: Develop increments in 2-4 week sprints with daily scrums
  3. Project Closure: Complete documentation, assess lessons learned

Functional vs Non-Functional (One-liner)

Functional: "The system SHALL DO ___" (services, features, actions)
Non-functional: "The system SHALL BE ___" (fast, secure, reliable, usable)
